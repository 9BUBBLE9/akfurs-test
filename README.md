# AK Furs — сверка выгрузок

Решение тестового задания: из сырых выгрузок (CRM, банковская выписка, справочник цен, переписки
с клиентами) одной командой собирается `answers.json` с ответами на вопросы Q1–Q4.
Записка руководителю и ответ клиентке (Q5) лежат в [Q5.md](Q5.md).

## Запуск

Нужен Python 3.10+.

**1. Данные.** Исходных файлов в репозитории нет (их просили не публиковать). Создайте в корне
репозитория папку `data/` и положите в неё четыре файла задания:

```
akfurs-test/
├── data/                                  ← создать и положить файлы
│   ├── 01_crm_orders_export.csv
│   ├── 02_bank_statement_rub.csv
│   ├── 03_catalog_prices_reference.xlsx
│   └── 04_client_chats.zip
├── solve.py
└── ...
```

Папка `data/` указана в `.gitignore` и в коммиты не попадёт. Можно использовать и любую другую
папку — её путь передаётся первым аргументом.

**2. Запуск.**

```bash
pip install -r requirements.txt
python solve.py data -o answers.json
```

- `data` — папка с исходными файлами. Имена файлов не важны: каждый файл узнаётся по
  содержимому (CSV CRM — по колонкам «Номер заказа», «№ строки», «Выгружено»; выписка — по
  «Дата операции», «Сумма», «Назначение платежа»; Excel — по листу «Прайс_история»; переписки —
  zip-архив с .txt). Каждого вида должно быть ровно по одному файлу.
- Без `-o` JSON печатается в консоль в UTF-8. В Windows PowerShell 5.1 перенаправление
  `> answers.json` сохраняет файл в UTF-16, поэтому лучше использовать `-o`.
- Предупреждения (незнакомый статус, менеджер, узнанный по имени и фамилии, расхождение сумм
  оплаты, похожее на приглашение сообщение и т. п.) выводятся в stderr — их стоит прочитать.
- Незнакомый формат даты, цены, артикула, менеджера и других полей, от которых зависят ответы,
  останавливает расчёт: печатается «ОШИБКА В ДАННЫХ» со списком проблем, сгруппированных по
  видам, и номерами строк файла; код выхода 2, `answers.json` не перезаписывается.

Тесты:

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Без папки `data/` тесты на настоящих выгрузках пропускаются (в выводе pytest — `skipped`),
остальные работают на небольших выдуманных примерах.

## Принятые толкования

Полный текст — в поле `notes` файла `answers.json` (он же в `NOTES` в [solve.py](solve.py)).
Коротко:

- **Дубли (Q1).** Строка заказа — пара «номер заказа + № строки»; из повторов остаётся версия с
  самым поздним «Выгружено». A-00075, А-75 (кириллица), a-75, A75 — заказ 75.
- **Даты.** Записи вида `NN/NN/ГГГГ` и `NN-NN-ГГГГ` читаются как день/месяц: порядок
  определяется по самим данным. Пятизначные числа — даты в формате Excel.
- **Скидка.** «N%» — от суммы строки; число без % — рубли на всю строку, а не на единицу.
- **Статусы.** Всё, что не «Оплачен», «Отменён» и не «Возврат», — «В работе» (NEW, «Ждём оплату»).
  Незнакомый статус определяется по первому слову («Отменён клиентом» → Отменён), кроме
  «Оплачен частично» и «не оплачен».
- **Менеджеры.** По листу «Менеджеры»; написание, которого там нет («Фамилия Имя», «И.Фамилия»),
  сопоставляется с «Имя Фамилия» по имени и фамилии, только если совпадение однозначно.
- **Платежи (Q2).** Учитываются только поступления, возвраты клиентам — нет. Номер заказа — код
  A/А-NNN или число после «заказ», «зак.», «счёт №», «order» (допустимы «№», «#», «:»); номер
  счёта считается номером заказа. Телефоны и даты в назначении платежа игнорируются. Номер
  должен существовать в CRM.
- **Цены (Q3).** Исключены только отменённые строки. Нарушение — цена за единицу после скидки
  строго ниже минимальной на дату создания заказа. Старый артикул всегда заменяется новым.
  В разбивке — только менеджеры с нарушениями.
- **Переписки (Q4).** Учитываются только сообщения менеджера. Цена — сумма с денежной единицей или
  прописью; «3-4 взноса», «40%», «с 11 до 20» — не цена. Приглашение — призыв приехать или
  записаться; адрес шоурума — не приглашение. Чат с приглашением, но без цены — нарушение.

## Как проверялся результат

- **Воспроизводимость:** чистый клон репозитория + копия данных → команда из `run_command` даёт
  `answers.json`, идентичный закоммиченному, повторный запуск — тот же результат.
- **Порядок строк:** строки CRM и выписки, а также файлы в архиве переписок перемешивались
  случайным образом пять раз — ответы не менялись.
- **Сверка сумм:** у всех 669 оплаченных заказов с поступлениями сумма платежей совпала с суммой
  заказа после скидок до копейки. Это подтверждает выбор дублей, разбор цен и скидок и то, что
  номер счёта — номер заказа. Сверка встроена в расчёт и на новых данных покажет расхождения
  предупреждением.
- **Q4:** вручную перечитаны все 22 найденных чата, разметка всех видов сообщений менеджера и
  все 52 суммы прописью.
- **«Новая версия» данных:** файлы переименованы, добавлены новые написания (даты `ДД-ММ-ГГГГ`,
  цены «49 000 ₽», менеджер «Фамилия Имя», статусы «Отменён клиентом» и «Оплачено полностью»,
  назначения «Оплата заказа: 1001» и «#605», приглашения «рады видеть вас», время
  `[2026-10-05 12:00]` в чатах) и изменены значения с заранее известным эффектом. Все ответы
  совпали с ожидаемыми; неоднозначные данные (цена «1,600», неизвестный менеджер, валюта USD,
  два файла выписки, смешанные ДД/ММ и ММ/ДД) дают понятную ошибку. Найденные при этом
  случаи покрыты тестами в [tests/test_new_formats.py](tests/test_new_formats.py).
